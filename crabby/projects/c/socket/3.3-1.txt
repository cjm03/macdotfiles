/*  
 *  Notes on C sockets
 *  via Columbia CS
 *-------------------------------------------------------------------------------------------------------
 *  Socket descriptor type: int
 *  Two byte orderings:
 *      Network Byte Order: Most significant byte (aka octet) first
 *          - aka Big-Endian Byte Order
 *      Host Byte Order: Lease significant byte first
 *--------------------------------------------------------------------------------------------------------
 *  sockaddr : holds socket address information for many types of sockets
 *  struct sockaddr {
 *      unsigned short  sa_family;    // address family, AF_xxx
 *      char            sa_data[14];  // 14 bytes of protocol address
 *  }
 *  sa_family can be a variety of things, but typically is AF_INET
 *  sa_data contains a destination address and port # for the socket
 *  To deal with sockaddr, programmers created a parallel structure sockaddr_in
 *  sockaddr_in : "in" for "Internet", makes it easy to reference elements of the socket address
 *  struct sockaddr_in {
 *      short int           sin_family;  // Address family
 *      unsigned short int  sin_port;    // Port number
 *      struct in_addr      sin_addr;    // Internet address
 *      unsigned char       sin_zero[8]; // Same size as struct sockaddr
 *  }
 *  sin_zero (included to pad the struct to the length of a struct sockaddr) should be set to all zeros with memset()
 *  *** A POINTER TO A struct sockaddr_in CAN BE CAST TO A POINTER TO A struct sockaddr AND VICE VERSA ***
 *      so, even though socket() wants a struct sockaddr*, you can simply cast a struct sockaddr_in.
 *  How can the entire struct in_addr be in Network Byte Order?
 *      struct in_addr {
 *          unsigned long s_addr;
 *      }
 *  Well, it used to be a union, but no longer. So, consider a struct sockaddr_in ina:
 *      to reference the 4-byte IP address (in Network Byte Order), you would call ina.sin_addr.s_addr
 *----------------------------------------------------------------------------------------------------------
 *  Network to Host Byte Order conversions
 *      Two types to convert: short (two bytes) and long (four bytes)
 *
 *      htons() - "Host to Network Short"
 *      htonl() - "Host to Network Long"
 *      ntohs() - "Network to Host Short"
 *      ntohl() - "Network to Host Long"
 *
 *  Why do sin_addr and sin_port need to be in Network Byte Order in a struct sockaddr_in, but sin_family doesnt?
 *      Because sin_addr and sin_port get encapsulated in the packet at the IP and UDP layers, respectively.
 *
 *      However, sin_family field is only used by the kernel to determine what type of address the structure 
 *      contains, so it must be in Host Byte Order.
 *
 *  Remember: Be Portable! Put your bytes in Network Byte Order before you put them on the network.
 *
*/
